# Bansuri Mastery App: Architecture

A static web app (no build server, no framework) in the style of Project Synapse. It teaches the
curriculum day by day, renders the curriculum's Markdown directly, and keeps all progress on the
learner's device. The MkDocs reference site is published alongside it at `/docs/`.

## Layout

```
index.html                 app shell (CSP, fonts, manifest, module entry)
manifest.webmanifest       PWA manifest
sw.js                      service worker: offline app shell + curriculum
app/
  app.css, fonts.css, icon.svg
  fonts/                   self-hosted woff2 (Hind, Rozha One, JetBrains Mono; OFL)
  vendor/marked.esm.js     Markdown parser (MIT), pinned 18.0.14
  data/plan.json           GENERATED by scripts/build_plan.py: the day-by-day plan
  data/files.json          GENERATED by scripts/build_app.py: list of curriculum files (for the SW and search)
  js/
    main.js                boot, hash router, layout
    state.js               progress model + storage (localStorage, versioned) + backup import/export
    util.js                DOM helpers (h(), text-only rendering), dates
    content.js             fetch + render Markdown, sanitize, rewrite links to app routes
    recorder.js            MediaRecorder + IndexedDB for recordings
    badges.js              badge rules
    errors.js              local error log for problem reports
    lessoncards.js         lessons as cards; playable.js: play buttons on notation
    games.js               games played with the mic: pitchSteer, balloon, fallingNotes, jam
    fun.js                 daily quests, points and levels, celebrate() (toast, chime, confetti)
    voice.js               the natural voice: pre-made clips (say, speak), captions, lesson read-aloud (tts-worker.js, Kokoro)
    demo.js                the animated flute (fingers, air) that plays a melody
    views/                 today, session, plan, reader, milestones, journal, progress, share, settings, bench, coach, play, compose, quick
    core/                  shared with the standalone Practice Bench (see below)
    bench/                 Practice Bench UI module
bansuri-mastery/           the curriculum (Markdown) - fetched by the app, also the MkDocs docs_dir
scripts/                   validate.py, gen_nav.py, build_bench.py, build_plan.py, build_app.py
tests/                     browser smoke tests (puppeteer-core + local Chrome/Edge)
```

## Navigation

Five tabs (`main.js` `NAV`): Today, Course, Practice, Play and Me. Related screens share a tab and get a small menu at the top (`GROUPS`): Course map and Library; Bench, Coach, Listen and Songs; Games, Make a melody and 5 minutes; Progress, Journal and Settings. `TAB_OF` maps every route to its tab. Simple mode has its own three tabs. The top bar shows the day and the level as one chip, and Settings.

Session steps are shown by name and icon (`steps.js` `STEP_META`) with their instruction in plain words (the spoken text from the voice index, in the learner's language); the plan's original wording is one tap away. Today puts the day's main action first, then the session at a glance; on wide screens a second column holds the level, quests and extras.

Today is for doing and Me is for seeing progress. Today: the Resume card (the streak inside it), at most one notice (help, backup or install, in that order), "Fix today" (the single weakest spot), the session and readings, and a progress card (level with "about N days to the next level", this week, quests). Me (Progress) is a dashboard of five questions: Am I improving? (trend charts of the longest steady note and play-along accuracy, by ear), Am I practising regularly? (last week, streak, calendar, minutes per week), Where am I in the course?, What should I work on? (weak spots), and Level and badges. A session lists every step as a row (a task list: number, icon, minutes, a tick when done); only the active step is open. The course map shows each phase as a path with a progress ring, a status and "Continue"; the Library shows lessons as a catalogue (taught on which day, done or in progress). Badges are hexagon emblems (`ui.js`). `palette.js`: "/" or the search button finds any screen, setting or course page.

## Coach (views/coach.js)

- Works offline: it reads the symptom table in `troubleshooting/README.md` and shows the likely
  causes plus the matching guide's quick checks, fixes, verification and "when to seek a teacher"
  sections. Editing the troubleshooting guides updates the coach; there is no separate data.

## Live listening (core/listen.js, core/live.js)

- `listen.js`: one shared microphone (`listenMic(fn)` gives about 30 readings a second, `{ t, semi, near, cents }`, with `t` on the audio clock) and the pure logic, unit-tested in `tests/live.test.mjs`: `holdTracker` (steady held note, short dropouts forgiven), `noteSequencer` (stable notes from the stream), `phraseMatcher`, `tapStats`. `muteListening(until)` keeps the app from hearing its own notes.
- `live.js`: widgets shared by the app and the standalone bench (bundled by `build_bench.py`): `holdMeter`, `phraseCheck`, `echoGame`, `tapGame`. Styles are the `lv-` classes in `bench.css`.
- Readings far outside a 6-hole bansuri's range (for example the tanpura's low strings) are ignored. Repeated notes (`G G G`) count once, because a tongued repeat has no pitch break to detect.
- Play-along "check me" mutes the melody (the learner plays it) and judges each note from the readings inside its time window.
- Interactive lessons (`views/lesson.js`, `lesson/player.js`): a lesson (`lessons/<id>.js`, listed in `lessons/index.js` with its day) is chapters of steps; each step kind (`lesson/steps.js`: listen, quiz, cards, choose, form, timer, beat, parts, holes, record; or custom) returns `{ el, destroy }` and calls `api.ready()` when done. Progress and choices are kept in `bansuri.lessons`; `lesson.finish(data)` records the result (M0: `finishSession` and `recordAttempt`). `lesson/flute.js` draws the flute whose parts and holes can be tapped.
- Sessions (`views/session.js`) show one block at a time; `holdSpec(block)` reads long-tone targets and hold times from the block text. Milestones (`views/milestone.js`) offer a microphone check where `micSpec(item, criterion)` recognises a hold or a phrase.
- Lessons (`lessoncards.js`) are split into cards from their own headings (long ones into parts); `playable.js` adds a play button to any code span that is pure notation.
- Results leave the widgets as a `bansuri:live` DOM event (`emitLive`); `livestats.js` stores them in `state.live` (`holds` per note per day, `echo` per level, `taps`, `plays`), shown on Progress and Today. The standalone bench has no listener, so nothing is stored there.
- `micIntro` explains the microphone once before the browser's own prompt. `fluteFinder` measures a held Sa and sets `saNote`, `saOct` and `a4`.
- Repeated notes: `noteSequencer` treats a volume dip and recovery on the same pitch as a new note (tonguing); `phraseMatcher` also accepts a repeat that was too smooth to hear once the next note arrives.
- Play-along timing is judged against a fixed detector delay (`DETECT_LAG`, 0.09 s), so a learner who is always early or late is told so. If every note arrives very late (over 0.3 s), the summary points at Bluetooth audio. The tap game's device delay comes from its calibration (`tapLatency`).
- Widgets open the microphone through `lvListen`, which closes a subscription that arrives after the widget was stopped, started twice or destroyed. Views return cleanups that destroy their widgets.
- Songs (`views/songs.js`, `#/songs`) are parsed from `exercises/EX-MEL-practice-melodies.md`; raga tools (`ragaInfo` in `views/reader.js`) read the Aroh, Avroh and Notes rows of a raga card.

## Voice, language and access (voice.js, core/i18n.js, core/fingers.js)

- **Voice clips.** `scripts/build_voice.py` turns everything known in advance into MP3 clips with Kokoro-82M (kokoro-onnx; English `af_heart`, Hindi `hf_alpha`): the phrases in `scripts/voice/phrases.json`, every session step in `scripts/voice/steps.json` (spoken English and Hindi), note names with "Hold", "That is", "Next", "Play", and numbers. Output: `app/voice/<lang>/<hash>.mp3` plus `index.json`. CI runs `--check` (no model needed). Clips are not precached; the service worker keeps each one in `voice-clips-v1` (never cleared by updates) when it is first played, or all at once from Settings.
- `speak(...refs)` plays clips back to back through the app's audio graph, mutes the microphone while it talks (`muteListening`) and shows a caption. `say()` does the same only when "Talk to me" is on. The shared widgets speak through `setSpeaker()` (the standalone bench has none): `holdMeter` judges each note when it ends (wrong note, sharp, flat, airy, short) and can play a guide glide to the target (`hints`).
- **Free text** (lesson cards): `readAloud(text)` runs Kokoro in a worker (`tts-worker.js`, vendored `app/vendor/kokoro`, not precached). The model is fetched from Hugging Face only after the learner agrees; the device's own speech synthesis is never used.
- **Countdown** (`core/live.js` `countdown(host, { btn })`): every start that listens or records (meters, phrase checks, play back, the flute finder, play-along check, the tuner, the coach, the microphone check, the games, `recordWidget` and the posture check) waits `settings.countdown` seconds (default 5, 0 = none) with ticks, a cancel button, Escape, or a second press of the start button. Tests set `window.__countdownSeconds`.
- **Hands-free sessions** (`views/session.js`): the step is spoken, its meter or timer starts, and `waitForNote(0)` (`core/listen.js`) moves on when the learner plays Sa after the goal or the time.
- **Hindi**: `core/i18n.js` translates every text node and label as it appears (`observe(document.body)`) from `app/i18n/hi.json` (exact strings and `{placeholder}` patterns). Course content is marked `translate="no"`. Session steps use the Hindi text from the voice index.
- **Settings** (`core/settings.js`): `lang`, `talk`, `notesAs` (letters or fingering pictures, `core/fingers.js`), `simple`, `textSize`, `easyFont`, `contrast`, `bigTargets`, `beatFlash` and `vibrate` (`audio.js` `onBeat`), `gameSpeed`, `noTimer`, `cues`, `hints`.

## Levels and XP (xp.js, levelui.js)

- `LEVELS`: 30 named levels (English and Hindi); level L starts at 250 x L x (L - 1) XP, so each step needs 500 more than the last. `levelOf(xp)` gives the level, its name in the current language and the progress to the next.
- `award(src, { key, amount, extra })` applies `RULES` (XP per source, daily caps, once-only keys such as a lesson path or milestone id) and a +10% streak bonus, stores `state.xp` (`total`, today's caps, once keys, XP per day, the latest 40 awards) and notifies `onXp` listeners: main.js floats "+N XP", updates the level badge and celebrates a new level.
- Sources: `course.js` (sessions, minutes, milestones, reviews), `lessoncards.js` and `views/reader.js` (flashcards, mastery items, finished lessons), `recorder.js`, `views/journal.js` and `views/quick.js` (minutes), quests (`fun.js`), and the `bansuri:live` results in main.js (bests, play back, play-along, tapping, every game round).
- Learners from before levels existed get XP rebuilt from their history (`xpFromHistory`), announced once.

## Habits, devices and help (reminder.js, backup.js, move.js, calibrate.js)

- `streakRun(dates, end)` (course.js): one missed day in any 7 is a rest day that keeps the streak; tested in core tests.
- `reminder.js`: the reminder time and the last practice day are kept in IndexedDB (`bansuri-meta`) so the service worker can read them; `periodicsync` ("practice-reminder") shows one notification a day after the time if nothing is logged. Chrome only, installed app; the calendar file is the fallback.
- `backup.js` `saveBackup()`: Web Share with the file where supported, else a download. `move.js`: progress and settings, gzip-compressed (CompressionStream) into `#/move/<z...>`; `views/move.js` compares and replaces on a second tap; Settings shows a QR code (vendored qrcode-generator, MIT) while the link is under 2,300 characters.
- Teacher link: `sharePayload(name, true)` adds minutes per week, longest holds, recent play-along and play-back; `views/share.js` shows them as a report. `views/students.js` keeps pasted links in `bansuri.students` (`{p, added}`; a newer link from the same name replaces the older) and decodes them with `share.js` `decode` for the table.
- Storage safety: `main.js` asks `navigator.storage.persist()` once started; Settings shows whether storage is protected. On iOS browsers (`today-cards.js` `iosBrowser`) the install card shows from Day 1 and returns weekly, and the backup nudge comes every 3 days (7 elsewhere), because Safari can clear a site's data after about a week without a visit.
- `news.js`: one "What's new" note (`NEWS.id`, dismissed into `prefs.newsSeen`). Today shows at most one notice: adaptive help, then news, then the backup nudge, then the install card.
- Lessons in Hindi: `app/i18n/lessons-hi.json` (sections keyed by their English heading); `lessonCards(node, path, hi)` swaps in the Hindi text with the English in a toggle; each lesson's explanation has a Hindi clip (`build_voice.py` "lessons").
- `calibrate.js`: four guided tasks record the detector's readings (no audio) to a JSON file for setting thresholds from real players. `scripts/hindi_review.py`: a CSV of every Hindi text for a native speaker, and `--apply` to write corrections back.
- The service worker precaches the app and a few core pages, then saves the rest of the course in the background ("CACHE_REST") once the app is open.

## Games, quests and challenges (games.js, fun.js, views/play.js)

- Games return `{ el, destroy }` and open the microphone through a helper with the same late-subscription guard as `lvListen`. Results go out as `bansuri:live` events with `type: "game"` (`game`: steer, balloon, falling, jam); falling notes also emits a `play` result.
- Courses come from `seeded(seed)` (mulberry32) and `nextNote(set, prev, rnd)`, so a challenge link (`#/challenge/<payload>`, decoded and validated by `decodeChallenge`) replays the same gates or balloons. Bests are kept per note set in `bansuri.game.<game>.best.<level>`.
- Falling notes judges each note from the readings in its window, with the detector delay `LAG` (0.09 s): perfect (in tune, first heard within 0.12 s), good, or miss.
- Quests: `questsFor(date, state)` picks two from a pool by the date (plus "finish today's session"), the same all day. `main.js` passes every live result to `advanceQuests`; 20 points per quest, 20 more for all three, 100 points per level. Stored in `state.live.quests` and `state.live.points`.
- `celebrate(text)`: a toast, a chime and confetti (no confetti with reduced motion), for new bests, quests and passed milestones.
- Play leads with one game (`views/play.js` `FOR_QUEST`: the game that moves the first undone quest on) and lists the rest under "More to play". Falling notes has a speed ladder (2 stars or more raises the next round by 8 BPM, up to 160); the jam has prompts checked from `run.played` when it stops.
- `holdMeter` draws `opts.ghost(target)` (the best hold, from `livestats.bestHold`) as a faint arc, and a glow from the detector's clarity (`r.clarity`). `playEvents` `onPreview`/`lead` lets play-along show the fingering 0.3 s before each note.

## Notation from a recording (transcribe.js, views/transcribe.js)

- Kept in the app: every capture or opened file goes to IndexedDB (`captures.js`, database `bansuri-transcribe`, up to 12, oldest dropped) with its name, length and, after Save, its notation and page settings; "Your recordings" opens, renames and deletes them, and Open restores the settings and the saved notation. Settings > Start over clears them too. Downloads are only for when a file is wanted.
- Sound: `getDisplayMedia` (a browser tab, with "Share tab audio"; desktop Chrome and Edge), `getUserMedia`, or a file; streams are recorded with MediaRecorder (up to 6 minutes), then decoded like a file. Nothing is uploaded or stored; only saved notation is kept (`bansuri.transcribed`).
- Pitch (`pitchTrack`, default `melodyTrack`): harmonic summation as in MELODIA. Every 20 ms a 2048-point FFT; its 30 strongest peaks vote for every pitch they could be harmonics 1-8 of (20-cent bins, 75-2200 Hz, weight 0.8 per harmonic); the 40th percentile of each bin over the whole recording is subtracted (a tanpura, drone or pad that never moves); a 5-frame median over time removes drum strokes; a dynamic programme picks a strong, smooth path (a cost per 20-cent step, or a fixed cost to jump). A very confident YIN reading exactly one or two octaves above the path wins (harmonic votes can settle an octave low on clean notes). Voicing: the path's strength against its median where there is sound. `engine: "yin"` keeps the old single-pitch tracker.
- Notes: `stableRuns` keeps stretches within 0.6 semitone of their recent average (vibrato stays one note), split at silences and at dips in loudness times melody strength (repeated notes), and drops anything under 80 ms. `labelNotes` names them with a slowly moving tuning reference (a dynamic programme over -0.6 to +0.6 semitone, then a second pass that makes rarely used notes less likely), because real flutes are not equal-tempered and players drift. `foldOctaves` moves a note more than 9 semitones from its neighbours' median by an octave or two when that brings it at least 6 closer (detector octave slips; real octave leaps stay). `graceNotes` turns a note under 130 ms that runs into a longer one into its kan. Notes more than 17 semitones from the median are dropped.
- `findTonic`: note durations by pitch class against a Sa template (Sa, Pa strongest), with bonuses for the first and (more) the last held note; the learner can pick another Sa and choose the part of the recording (`from`, `to`). `estimateTempo` and `beatFit`: phase coherence of note starts, 40-180 BPM, prior near 95 BPM.
- Which notation (stereo recordings only; `stereoDown` measures side against mid energy, under 2% counts as mono): "Whole song" (default, the mix), "Singer" and "Background" (`partSpectrum`: per FFT bin, the centre share from the left-right difference against the sum; the singer keeps the centre of the mix, the background the sides; bass and drums go with the singer), and "Best to play" (`bestRuns`: the singer's stretches plus the background's in singer gaps of 2 s or more, named together with one tuning; `phraseOctaves` moves each phrase as a whole into the flute's range; the main-melody range filter is skipped). Singer and background are worked out the first time they are chosen. A mono recording is split by repetition instead (`repetitionParts`, REPET-SIM: per 0.1 s block, the median spectrum of the 10 most similar blocks at least 1 s away is the background, the rest the singer; the pitch is then read from the whole mix within a semitone of the singer's line). On a synthetic mono song with harmonium and tabla it keeps the melody right where the whole mix fails, but on a real film song whose verses repeat the same tune the singer lands in the background; the page says so. Measured on a synthetic stereo song (violin intro and outro panned left, singer, drum and drone in the centre, a soft panned pad): 0% wrong for all three; a mono file greys them out.
- `mainMelody` (default; "Every note" turns it off): leaves out notes outside the melody's main range (10th to 90th percentile of time, plus or minus 3 semitones: an instrument above or below the singer in an interlude), notes weaker than a fifth of the median strength, and notes under 100 ms; grace notes only with "Every note".
- Layouts: `toPhrases` (default: the notes in order, easy to read, "-" per extra beat, "," at a pause; the page plays unedited notation with the notes' real timing) and `toNotation` (bars and beats: notes snap to 1, 2 or 4 steps per beat; gaps under 3/4 of a beat are held, not rests). Flutes: "same key" writes semis from the flute's Sa (`bestFlute` names the matching flute), "own key" keeps the recording's sargam; `bestOctave` and `fitOf` keep it inside .P to M'.
- MIDI files (`midi.js`): `parseMidi` reads format 0/1/2 (running status, meta tempo, key and time signatures, every tempo change for seconds, SMPTE time), `melodyScore` ranks tracks (one note at a time, singing range, a melody-like name, enough notes; drums out), `topLine` keeps the top note where notes overlap, `keyTonic` gives Sa from the key signature. The notes go to `transcribe` as `o.notes` (used exactly, with the file's tempo and the beat at 0); the arrangement is rendered offline (simple oscillators, the melody louder) so listening and Check by ear work as for a recording.
- Check by ear (`views/eartools.js`): a canvas of the pitch line and the notes over a window of 3 to 60 s (scroll, zoom), rows sized to the notes in view; a note is picked by click or arrow keys; the original is heard through an `<audio>` element with `preservesPitch` at 50, 75 or 100% (here, the phrase to a pause of 0.6 s, looped), and "phrase, then notes" plays the notes as written at the recording's pitch and the same speed. Edits (semitone, octave, shorter, longer, split, join, the pitch heard under the note, add after or by double-click, delete; a drag scrolls) go to the page, which copies the notes found into `manual` on the first edit, keeps 100 undo steps, regenerates the notation through `o.notes`, and saves `manual` with the recording.
- Tap the beat: taps while the part plays (button or T) give the tempo (median gap) and where beats fall (circular mean of the taps), used as `o.phase`. The notation can go to the Songs page ("My songs", `bansuri.mysongs`), be saved as a one-track MIDI file of the notes as corrected, or printed (print CSS shows only the notation). A sticky bar links the steps.
- Separation model (`demucs.js`, `separate-worker.js`, `separator()` in `analyser.js`): HTDemucs (Meta, MIT) exported to ONNX (`timcsy/demucs-web-onnx`, pinned revision, about 172 MB), run by ONNX Runtime Web 1.31 (`app/vendor/ort`, WebGPU, else WebAssembly on the processor; loaded only when used, not precached). The model is downloaded once after the learner chooses it and kept in the Cache API (`demucs-model-v1`, "Remove the model" deletes it). The recording is resampled to 44.1 kHz stereo (OfflineAudioContext), separated 7.8 s at a time with a quarter overlap (input and output steps from demucs-web, `app/vendor/demucs`, MIT), keeping two stems as mono: vocals (Singer) and other (Background); each goes through the usual melody tracker ("track" job). The two pitch lines are saved with the recording (`sep` in the capture), so it opens again without separating; the vocals can be heard alone and Check by ear plays them for the Singer notation. Node tests run the same code with onnxruntime-node (`tests/separate-node.mjs`); `tests/separate-browser.mjs` runs it in headless Chrome.
- Default key: the sargam is written from the song's own Sa ("My flute's own key"), as tutorials and song books write it; "Same key as the recording" is for playing along with the recording.
- Off the page (`analyser.js`, `transcribe-worker.js`): decoding stays on the page; down-mixing, the pitch of every 20 ms and the singer and background separation run in a module Web Worker (`runJob`: "load", "whole", "part"), with progress messages and Cancel (the worker is stopped and started afresh; the recording is loaded again when needed). Where a module worker cannot start, the same jobs run on the page.
- Beats (`beatGrid`): a steady pulse, or with "Follow tempo changes" (on by default) beat tracking by dynamic programming over beat time and beat length (onsets from the note starts, every 10 ms; a cost for each change of beat length and a little for straying from the estimated tempo), a MIDI file's tempo map (`beats` from `parseMidi`), or the learner's taps where they tapped. The notation is written on that grid; `lineTimes` gives each line's start, and a line's time on the page plays it.
- Scale (`scaleOf`): note time by pitch class from Sa against the ten thaats, or, with exactly five notes, six pentatonic ragas; notes outside it are marked odd (outlined in Check by ear, "Next odd note", a chip). It names notes, not ragas.
- Slides (`slides`, `markGlides`): frames in a steady monotonic glide of 0.6 semitone or more over 140 ms are kept out of the notes; a voiced gap of 80-600 ms moving from one note to the next marks the second as a glide (written "~", played as a ramp). The easier version (`easier`): quick runs fold into the note before, ornaments go, phrases move into the easy range, rare passing half-holes become a neighbouring open note.
- Practise a line with the recording: the line loops through an `<audio>` element (pitch kept) at 50, 75 or 100%, the microphone's readings are timed against it, and `scoreTake` marks each note right, another octave, another note or not heard; 80% right steps the speed up.
- Backup (`backup.js`, `state.js`): progress, settings and the learner's own lists (My songs, saved notations, compositions and others), and with recordings the Transcribe recordings with their notation and corrections.
- Playback: notes are made about 1.5 s ahead of time (`playEvents`, `playFound`, `playTimed`), never all at once, which made long pieces crackle. A tab left open checks for a new version every 30 minutes and when shown again (main.js), and takes it at the next screen change.
- The page: get the sound; what was found (chips, pitch line, settings in three groups); the notation drawn as bar or phrase boxes (editable as text); listen and compare (the recording, the notation, and both together: the notes found played as a flute at their own times over the recording); play along (the bench player). Each player has a Download button: the part of the recording, the notation (rendered with `makeVoice` into an OfflineAudioContext; `opts.ctx` and `opts.dest`), or both, saved as a 16-bit WAV. The notation shows as the plain sargam text in equal-width cells (S R G or Devanagari, in the body font), with Edit for the text box.
- Guided check (`eartools.js`, with `noteDoubts` and `noteChoices` in transcribe.js): "Check line by line" plays each phrase sung, then as written; Enter marks it right (op "ok", saved with the corrections), or the line is fixed with the keys. "Check the doubtful notes" visits only notes outside the scale, heard 35 cents or more off, wavering, or a big jump, and offers the likely notes (as written, the pitch heard, the scale neighbours, the octave) as one-key choices.
- Accuracy research (tests/song-bench.mjs on 14 songs against flutesangam.com and two tutorials, kept outside the repo): with the right Sa, about 70% of the tutorials' notes are written right, whatever the method: the app's tracker on Demucs vocals 69%, RMVPE 68%, the ROSVOT note transcription model (MIT, run in Python) 68%, ROSVOT's timing with the app's pitch naming 71%. Relaxing or tightening the note filters, splitting at syllable valleys, and letting repeats of a line vote on each note all moved the score by 2 points or less. In lines found twice or more, 79% of notes are as written, 5% differ the same way every time (the recording and the notation disagree) and 16% are slips that differ between repeats. Published note-level singing transcription on full pop songs (MIR-ST500) reaches about 70% too. The doubtful-note check flags too few of the errors to reach 90% (projected 71% to 74%), so line-by-line checking by ear is the way to 90-100%.
- Frames are centred: each 20 ms frame is analysed with half a window of silence in front, so frame i is the sound heard at i x 20 ms (before, notes came about 46 ms early).
- Benchmark (`tests/melody-bench.mjs`, not in CI): the ADC2004 and LabROSA MIREX-05 clips (33, with the melody's pitch every 6-10 ms) are downloaded once to the temp folder and scored as in MIREX (raw pitch and chroma accuracy, voicing); `--notes` scores the notes written, `--sep` the separated vocals.
- Measured: `tests/transcribe.test.mjs` (synthetic: voice, flute, drone, low voice, chords and tabla at up to the melody's level all 0% wrong; harmonium chords in the melody's own octave break it, printed) and `tests/transcribe-real.mjs` (real bansuri recordings in app/audio: scales 0-7% wrong, Sa right on all with a known Sa).

## Course features (app side)

- `placement.js`: the playing placement test (six items, checked by microphone) recommends a phase.
- `course.js` `getDay`: applies the learner's pace (`prefs.pace`: short 0.6, standard 1, long 1.3 times every block's minutes) and rotates the generic warm-up text through five variants.

## Tone, posture and real recordings

- `pitch.js` `toneEstimate`: from a recording, the share of sounding frames with a clear pitch, the mean periodicity (`periodicity()`, a threshold-free YIN measure) and the steadiness of held notes give a 1-4 tone estimate. Thresholds are calibrated on synthetic tones and on the four demo levels (`audio.js` `TONE_LEVELS`, `toneDemo`), which measure as 1, 2, 3 and 4; real-room accuracy still needs checking against a teacher.
- `audio.js` `makeVoice`: a bansuri-like voice (strong fundamental, breath noise around the fundamental and second harmonic, a short chiff, a pitch scoop, delayed vibrato); `opts.breath`, `opts.wobble` and `opts.body` make the tone demos.
- `posture.js`: MediaPipe pose landmarker (vendored in `app/vendor/pose`, loaded only on demand, not in the offline download) and `postureChecks(landmarks)`: shoulders level and not raised, head level, flute roughly level, elbows relaxed. The vendored bundle's telemetry sender is replaced by a no-op; the CSP adds `'wasm-unsafe-eval'` for WebAssembly only.
- Lessons' last cards play a bundled real-bansuri recording (`lessoncards.js` `BUNDLED`) until the learner marks their own reference.

## Progress model (state.js)

```jsonc
{
  "v": 1,
  "startedAt": "2026-10-30",
  "current": 3,                       // current practice day
  "days": { "1": { "done": true, "date": "2026-10-31", "blocks": {"W": true}, "minutes": 48, "note": "...", "passed": true } },
  "milestones": { "M1": { "status": "passed"|"failed"|"open", "attempts": [{ "date", "items": {"1": true}, "rubric": {"T":3,...}, "notes" }] } },
  "reviews": { "<itemId>": { "label", "learned": "date", "next": "date", "stage": 0..5 } },
  "log": [{ "date", "minutes", "day", "note" }],
  "ear": { "2": {"right": 0, "total": 0} },
  "badges": { "<id>": "date" }
}
```

Spaced review intervals after learning an item: 1, 3, 7, 14, 30, 60 days.
Gating: a milestone day must be passed before `current` can move past it. A failed milestone
shows its remedy table and a retest button; practice continues with "practise again" sessions.

Recordings live in IndexedDB `bansuri` / store `recordings`:
`{ id, date, day, label, mime, blob, durationS, kind: "audio"|"video", analysis?, ref?, refLabel? }`. They are never uploaded. A backup
export can include them (base64) or not.

## Security

- CSP: `default-src 'self'`; scripts only from this site; no `eval`; `connect-src` is this site plus Hugging Face, used only to download the reading-voice model after the learner agrees (the text read never leaves the device).
- Markdown is rendered with marked, then sanitized with an allowlist (no script, iframe, form,
  `on*` attributes, `javascript:` URLs). Text from the learner (notes, labels) is always inserted as text.
- Microphone is used only after the learner presses Record or Start microphone; the camera only for
  the video self-check.
- Shared origin: all `jenilmistryhq.github.io` projects share one origin, so they could read each
  other's localStorage. Use a custom domain if that matters.

## Offline and updates (sw.js)

- Network first for every file, with a short timeout, and the cache as the fallback. Online, a page is
  built entirely from fresh files; offline, entirely from the saved copy. A page never mixes versions,
  which matters because ES modules import each other by name.
- A new worker installs, saves every file listed in `files.json`, and takes over at once. An open page
  reloads at its next screen change (never mid-session). If a mismatch still happens, the error screen
  offers "Update and reload", which clears the saved copies.
