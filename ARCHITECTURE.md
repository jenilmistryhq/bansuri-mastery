# Bansuri Mastery App: Architecture

A static web app (no build server, no framework) in the style of Project Synapse. It teaches the
curriculum day by day, renders the curriculum's Markdown directly, and keeps all progress on the
learner's device. The MkDocs reference site is published alongside it at `/docs/`.

## Layout

```
index.html                 app shell (CSP, fonts, manifest, module entry)
manifest.webmanifest       PWA manifest
sw.js                      service worker: offline app shell + curriculum
app/
  app.css, fonts.css, icon.svg
  fonts/                   self-hosted woff2 (Hind, Rozha One, JetBrains Mono; OFL)
  vendor/marked.esm.js     Markdown parser (MIT), pinned 18.0.14
  data/plan.json           GENERATED by scripts/build_plan.py: the day-by-day plan
  data/files.json          GENERATED by scripts/build_app.py: list of curriculum files (for the SW and search)
  js/
    main.js                boot, hash router, layout
    state.js               progress model + storage (localStorage, versioned) + backup import/export
    util.js                DOM helpers (h(), text-only rendering), dates
    content.js             fetch + render Markdown, sanitize, rewrite links to app routes
    recorder.js            MediaRecorder + IndexedDB for recordings
    badges.js              badge rules
    errors.js              local error log for problem reports
    lessoncards.js         lessons as cards; playable.js: play buttons on notation
    views/                 today, session, plan, reader, milestones, journal, progress, share, settings, bench, coach
    core/                  shared with the standalone Practice Bench (see below)
    bench/                 Practice Bench UI module
bansuri-mastery/           the curriculum (Markdown) - fetched by the app, also the MkDocs docs_dir
scripts/                   validate.py, gen_nav.py, build_bench.py, build_plan.py, build_app.py
tests/                     browser smoke tests (puppeteer-core + local Chrome/Edge)
```

## Routes (hash-based, work on GitHub Pages)

| Route | View |
|---|---|
| `#/` or `#/today` | Today: the current practice day, due reviews, streak |
| `#/day/<n>` | A specific day (read-only if not reached; the current day is playable) |
| `#/session/<n>` | Guided session for day n: timed blocks with embedded tools |
| `#/plan` | Course map: phases, weeks, days, milestones and where you are |
| `#/read/<path>[#anchor]` | Render a curriculum Markdown file, e.g. `#/read/lessons/L04-first-sound.md` |
| `#/milestone/<id>` | Milestone test: checklist, rubric, pass/fail, remedies |
| `#/journal` | Practice log, recordings, analysis, comparisons |
| `#/progress` | Stats, streak calendar, badges |
| `#/share/<payload>` | Shareable progress card (payload is base64url JSON, no server) |
| `#/bench` | Full Practice Bench |
| `#/songs` | Song library: every practice melody with play-along |
| `#/coach` | Offline coach: diagnose a problem from the troubleshooting guides (`#/teacher` redirects here) |
| `#/library` | Every course page, grouped, with full-text search |
| `#/settings` | Flute Sa, A4, sound, theme, daily reminder (.ics), placement, backup, reset |

## Coach (views/coach.js)

- Works offline: it reads the symptom table in `troubleshooting/README.md` and shows the likely
  causes plus the matching guide's quick checks, fixes, verification and "when to seek a teacher"
  sections. Editing the troubleshooting guides updates the coach; there is no separate data.

## Live listening (core/listen.js, core/live.js)

- `listen.js`: one shared microphone (`listenMic(fn)` gives about 30 readings a second, `{ t, semi, near, cents }`, with `t` on the audio clock) and the pure logic, unit-tested in `tests/live.test.mjs`: `holdTracker` (steady held note, short dropouts forgiven), `noteSequencer` (stable notes from the stream), `phraseMatcher`, `tapStats`. `muteListening(until)` keeps the app from hearing its own notes.
- `live.js`: widgets shared by the app and the standalone bench (bundled by `build_bench.py`): `holdMeter`, `phraseCheck`, `echoGame`, `tapGame`. Styles are the `lv-` classes in `bench.css`.
- Readings far outside a 6-hole bansuri's range (for example the tanpura's low strings) are ignored. Repeated notes (`G G G`) count once, because a tongued repeat has no pitch break to detect.
- Play-along "check me" mutes the melody (the learner plays it) and judges each note from the readings inside its time window.
- Sessions (`views/session.js`) show one block at a time; `holdSpec(block)` reads long-tone targets and hold times from the block text. Milestones (`views/milestone.js`) offer a microphone check where `micSpec(item, criterion)` recognises a hold or a phrase.
- Lessons (`lessoncards.js`) are split into cards from their own headings (long ones into parts); `playable.js` adds a play button to any code span that is pure notation.
- Results leave the widgets as a `bansuri:live` DOM event (`emitLive`); `livestats.js` stores them in `state.live` (`holds` per note per day, `echo` per level, `taps`, `plays`), shown on Progress and Today. The standalone bench has no listener, so nothing is stored there.
- `micIntro` explains the microphone once before the browser's own prompt. `fluteFinder` measures a held Sa and sets `saNote`, `saOct` and `a4`.
- Repeated notes: `noteSequencer` treats a volume dip and recovery on the same pitch as a new note (tonguing); `phraseMatcher` also accepts a repeat that was too smooth to hear once the next note arrives.
- Play-along timing is judged against a fixed detector delay (`DETECT_LAG`, 0.09 s), so a learner who is always early or late is told so. If every note arrives very late (over 0.3 s), the summary points at Bluetooth audio. The tap game's device delay comes from its calibration (`tapLatency`).
- Widgets open the microphone through `lvListen`, which closes a subscription that arrives after the widget was stopped, started twice or destroyed. Views return cleanups that destroy their widgets.
- Songs (`views/songs.js`, `#/songs`) are parsed from `exercises/EX-MEL-practice-melodies.md`; raga tools (`ragaInfo` in `views/reader.js`) read the Aroh, Avroh and Notes rows of a raga card.

## Other app features

- **Video self-check** (Journal): `recordWidget({video: true})` records camera plus microphone at
  640x480. The live preview is mirrored; the saved video plays unmirrored. Items are stored with
  `kind: "video"` in the same IndexedDB store as audio.
- **Tabla theka** (Bench > tala): `tablaBol()` in `core/audio.js` synthesises each bol from a tuned
  dayan (at Sa/2) and a bayan; compound bols are split across the beat. "Clicks" remains an option.
- **Error log** (`errors.js`): window errors, failed resource loads and unhandled rejections are kept
  locally (`bansuri.errors`, last 30). Settings > Problem report copies them with the app version and
  browser; nothing is sent automatically.
- **CSV export** (Settings): the practice log and milestone attempts, with formula-safe quoting.
- **Reference audio:** `app/audio/` holds public-domain samples as Ogg Vorbis and AAC (`.m4a`, for
  Safari), made by `scripts/convert_audio.mjs`.

## Shared settings (core/settings.js)

`localStorage['bansuri.settings']` = `{ saNote: 0..11, saOct: 4|5, a4: 415..466, volume: 0..1 }`,
defaults `{0, 5, 440, 0.75}` (Sa = C5). Read/write only through `core/settings.js`:
`getSettings()`, `setSettings(patch)`, `saHz()`, `saMidi()`, `onSettings(fn)`.

## Bench module (app/js/bench/bench.js)

```js
mountBench(container, {
  tabs,        // optional subset of ['chart','play','rhythm','check','ear','about']; default all
  tab,         // initial tab
  notation, bpm, preset,    // preload the notation player (preset = exact PRESETS title)
  tala, talaBpm,            // preselect tala
  earLevel,                 // '2'|'3'|'4'|'6'
  checkPlan,                // index into CHECK_PLANS
  compact,                  // true inside a session: no page header, smaller flute
  onEar(result),            // {level, correct: bool} after each answer
  onCheck(rows),            // after a recording/tuner check
}) -> { destroy(), setTab(name), loadNotation(text, bpm), stopAll() }
```

The standalone `bansuri-mastery/tools/practice-bench.html` and the artifact fragment
`bansuri-mastery/tools/interactive-flute.html` are GENERATED by `scripts/build_bench.py`, which
bundles `core/*.js` + `bench/bench.js` + `bench/bench.css` into one file.

## Plan data (app/data/plan.json)

```jsonc
{
  "version": 1,
  "phases": [{ "id": 0, "title": "Setup", "doc": "phases/phase-0-setup.md", "firstDay": 0 }],
  "lessons": { "L04": { "title": "First Sound", "path": "lessons/L04-first-sound.md" } },
  "milestones": [{ "id": "M1", "title": "First Stable Tone", "path": "projects/M1-first-stable-tone.md", "day": 14 }],
  "templates": { "<id>": { "blocks": [ /* Block */ ] } },
  "days": [ /* Day */ ],
  "cycle": { "from": 600, "to": 683 }   // optional: repeat these days after the end (Phase 5)
}
```

**Day:** `{ n, phase, week, kind, title, minutes, lessons: ["L02"], template?: "<id>", blocks?: [Block],
pass?: "pass check text", milestone?: "M1", newItems?: [Item], doc?: "phases/...md#anchor" }`.
`kind` is one of `setup | practice | review | milestone`. If both `template` and `blocks` exist,
`blocks` wins. Day `n` is a **practice day** (not a calendar day).

**Block:** `{ id: "W"|"T"|"K"|"M"|"E"|"R"|"READ"|"TEST", label, minutes, text,
read?: [{ label, path, anchor? }], bench?: <mountBench options subset>, record?: "label" }`.

**Item** (for spaced review): `{ id, label, bench?: {...} , read?: {...} }`.

## Progress model (state.js)

```jsonc
{
  "v": 1,
  "startedAt": "2026-10-30",
  "current": 3,                       // current practice day
  "days": { "1": { "done": true, "date": "2026-10-31", "blocks": {"W": true}, "minutes": 48, "note": "...", "passed": true } },
  "milestones": { "M1": { "status": "passed"|"failed"|"open", "attempts": [{ "date", "items": {"1": true}, "rubric": {"T":3,...}, "notes" }] } },
  "reviews": { "<itemId>": { "label", "learned": "date", "next": "date", "stage": 0..5 } },
  "log": [{ "date", "minutes", "day", "note" }],
  "ear": { "2": {"right": 0, "total": 0} },
  "badges": { "<id>": "date" }
}
```

Spaced review intervals after learning an item: 1, 3, 7, 14, 30, 60 days.
Gating: a milestone day must be passed before `current` can move past it. A failed milestone
shows its remedy table and a retest button; practice continues with "practise again" sessions.

Recordings live in IndexedDB `bansuri` / store `recordings`:
`{ id, date, day, label, mime, blob, durationS, kind: "audio"|"video", analysis?, ref?, refLabel? }`. They are never uploaded. A backup
export can include them (base64) or not.

## Security

- CSP: `default-src 'self'`; scripts only from this site; no `eval`; `connect-src 'self'` (the app talks to no other server).
- Markdown is rendered with marked, then sanitized with an allowlist (no script, iframe, form,
  `on*` attributes, `javascript:` URLs). Text from the learner (notes, labels) is always inserted as text.
- Microphone is used only after the learner presses Record or Start microphone; the camera only for
  the video self-check.
- Shared origin: all `jenilmistryhq.github.io` projects share one origin, so they could read each
  other's localStorage. Use a custom domain if that matters.

## Offline and updates (sw.js)

- Network first for every file, with a short timeout, and the cache as the fallback. Online, a page is
  built entirely from fresh files; offline, entirely from the saved copy. A page never mixes versions,
  which matters because ES modules import each other by name.
- A new worker installs, saves every file listed in `files.json`, and takes over at once. An open page
  reloads at its next screen change (never mid-session). If a mismatch still happens, the error screen
  offers "Update and reload", which clears the saved copies.
